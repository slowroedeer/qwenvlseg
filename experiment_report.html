QwenVLSeg 实验报告
基于 Qwen3-VL-Seg (May 2026) 的轻量化复现

1. 研究背景与目标

Qwen3-VL-Seg 是阿里在 2026 年 5 月发布的视觉-语言分割模型，将 Qwen3-VL 的多模态理解能力扩展到像素级分割。原论文采用两阶段训练（grounding 预训练 + 分割微调），利用 LoRA 训练 LLM 输出结构化的 bbox 与 mask 标记。

本实验使用 Qwen3-VL-2B-Instruct 的 ViT 编码器和 LLM 解码器，训练约 5M 参数的 Mask Decoder。推理采用两遍前向策略，第一遍由 LLM 自回归生成 bbox，代码在生成的 JSON 中程序化插入 mask token，第二遍前向提取 LLM 隐藏状态作为语义查询。该查询与 bbox 编码、多尺度 ViT 特征融合后，经 2 层 Transformer Decoder 和迭代精炼模块预测分割掩膜。训练在 GT bbox 上施加 ±10% 扰动噪声以增强对 LLM 包围框偏差的鲁棒性。

2.2 Mask Decoder 关键模块

接收ViT 多尺度视觉特征、LLM 语义查询和bbox 空间先验三个输入，输出目标实例的二值分割掩膜。

① Multi-scale Spatial Feature Injection

ViT 不同深度的特征图粒度不同，从 ViT 的三个不同深度提取特征图，浅层保留细节、深层捕获语义，对每个尺度做 1×1 通道投影后，用 3×3 深度可分离卷积增强局部感受野，统一上采样到最小空间尺寸并拼接融合。

② Box Encoder

将 bbox 坐标 [x1, y1, x2, y2] 转换为 (x1, y1, log(w), log(h)) 四个标量，每个标量做傅里叶位置编码（32 频率），拼接后经 2 层 MLP 映射到 256 维。

③ Query Construction

语义查询 h_mask（mask token 位置的 LLM 隐藏状态）经线性层投影，与 bbox 编码相加后做 LayerNorm。

④ Memory Construction

Memory 由三部分相加：LLM 处理过的图像 token 特征（Tmm）+ 融合视觉特征（Ffuse）+ 可学习 2D 位置编码（Pmem）

⑤ Box-Guided Pixel Fusion

从 bbox 生成软空间门控（bbox 扩大 15%，每像素 4 个 sigmoid 项相乘），将 stride=4 的浅层 CNN 特征与上采样 4× 的 Ffuse双路像素融合。

⑥ Iterative Mask-Aware Query Refinement

两轮预测：第一轮 mask → 目标感知特征池化 → 精炼 query → Transformer Decoder 再次处理 → 第二轮 mask + IoU score。

6. 遇到的问题及解决方案

问题 1：LoRA 文本生成训练与基座模型原生能力冲突

现象：采用 LoRA（rank=8）训练 LLM 输出含 bbox 和 mask token 的结构化 JSON，训练 20 epoch 后模型生成完全崩溃，输出 <|im_start|> 循环序列。而未经训练的基座模型在测试图像上可以稳定、准确地输出 bbox JSON。进一步的 token 级别诊断表明，训练目标中 assistant\n 后的首个 token 与基座模型在该位置的强先验 token（始终为 \n）严重冲突，LoRA 的有限容量（约 8M 参数）无法克服该先验。

根因：LoRA 本身并非问题根源，问题在于 LoRA + 极小规模单一数据 + 冻结的目标输出格式三者叠加。原论文能够在 LoRA 训练中保持 grounding 能力，是因为其 grounding 预训练阶段使用了大规模多任务混合数据——RefCOCO、COCO、GRIT 等多个数据集，数百万样本、数十类任务。LoRA 的梯度分散在丰富的数据分布上，不同任务的优化方向相互制衡，。而本实验仅有约 600 张 VOC person 图像，单一类别、单一 prompt 模板、单一输出格式，LoRA 在极窄的数据分布上反复施加同方向的梯度更新，最终覆盖了 2B 基座模型中形成稳定 bbox 输出通路的关键参数节点，使模型回退到底层语言先验（输出换行和空格序列），不再走 grounding 通路。

解决：将 LLM 与 ViT 冻结。推理改用两遍前向策略，LLM 仅作为特征提取器参与 mask 生成。可训练参数从约 13M 降至约 5M，消除了 LoRA 破坏原生能力的风险。

问题 2：推理管线中的技术实现问题

现象一：手动 token 生成结果异常。在冻结 LLM 方案中，最初采用手动逐 token 调用 self.llm_decoder() 结合 _get_lm_logits() 进行自回归生成，输出序列的首个 token 为错误的 ``` 而非预期的 \n，与基座模型原生行为不一致。

现象二：ViT 输出特征异常。将归一化后的 tensor（shape [C, H, W]，值域 [0, 1]）直接传入 processor(images=[tensor])，导致 ViT 编码的特征图失真，下游分割结果退化。

根因：现象一的根因在于 resize_token_embeddings() 操作后，HuggingFace 的 generate() 方法内部会自动将 lm_head 权重与 embedding 表重新绑定（weight tying），而手动调用底层 llm_decoder 和 lm_head 绕过了这一机制，导致 logits 计算使用了未对齐的权重。现象二的根因在于 Qwen3-VL 的 processor 在设计上期望接收 PIL Image 对象，内部包含特定的 resize、归一化和 patch 嵌入预处理逻辑；直接传入 tensor 会跳过这些步骤，致使 ViT 接收到的 pixel_values 与训练分布不一致。

解决：针对现象一，统一使用 self.base_model.generate() 执行自回归生成，确保与 HF 官方推理路径一致。针对现象二，在调用 processor 前将 tensor 转换为 PIL Image：Image.fromarray((tensor.cpu().numpy()*255).astype(np.uint8).transpose(1,2,0))。

问题 3：LLM bbox 与 GT bbox 分布偏差导致 mask decoder 泛化不足

现象：将训练好的 mask decoder 分别用 GT bbox 和 LLM 生成的 bbox 进行评估，mIoU 分别为 0.80 和 0.61，两者之间存在约 0.19 的显著性能差距。这表明 mask decoder 在精确 bbox 下表现良好，但对 LLM 的近似 bbox 缺乏鲁棒性。

根因：训练阶段 mask decoder 的 bbox 输入始终来源于 GT mask 计算得到的精确包围框，而推理阶段的 bbox 来源于 LLM 的自回归生成。LLM 生成的 bbox 存在系统性坐标偏差（例如 x1 偏差可达 138 px），但 mask decoder 的 box-guided 组件——包括软空间门控（soft gate）和空间特征注入——对 bbox 的定位精度较为敏感，近似 bbox 会导致空间注意力图的焦点偏移，进而影响特征采样位置和最终分割精度。

解决：在训练过程中对 GT bbox 施加随机扰动：四个角点各自独立添加 ±10% 范围内的均匀噪声（相对于 bbox 的宽高），扰动后的 bbox 用于 mask decoder 的前向计算，而损失计算仍使用原始的 GT mask。该策略使 mask decoder 在训练中即暴露于不精确的 bbox 输入，学会在 bbox 存在偏差时仍能定位正确的目标边界。实施后 LLM bbox 下的 mIoU 从 0.61 提升至 0.72（+0.11），且 GT bbox 下的上限性能未受影响。

问题 4：多人场景中非首个实例信息丢失

现象：在包含多个 person 实例的图像中，LLM 可以检测并输出多个实例的 bbox（如 3 人则输出 3 组坐标），但早期实现仅使用 JSON 数组中的第一个元素（data[0]），其余实例的 bbox 被直接丢弃。这导致多人场景下预测 mask 仅覆盖了第一个实例，GT 人像像素的覆盖率仅为 60–70%。

根因：bbox 解析函数 _parse_bbox_from_text 的设计假定每张图像仅存在一个目标实例，直接索引数组首元素后返回。该假设在多人场景下不成立。

解决：将解析函数重构为 _parse_bboxes_from_text，返回 LLM 检测到的全部 bbox 列表。对于每个 bbox 独立运行 mask decoder 生成该实例的分割候选，最终通过 pixel-wise max 操作将所有候选合并为单一输出 mask。该策略使 mIoU 从 0.72 进一步提升至 0.754（+0.034），多人场景的 GT 像素覆盖率从 65% 提升至 85–98%，且单人场景不受影响（max 操作在 N=1 时退化为恒等）。
